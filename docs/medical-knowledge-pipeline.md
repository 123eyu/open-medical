# 医学知识库处理与检索

知识库分别保存原始资料、可回查的正文、派生索引和待核对的结构化知识。文件处理完成、语义索引完成、结构整理完成及来源复核是不同状态。

## 入库

知识库页面的两种上传方式均保存原文件，再由后台处理全文。“仅建索引”不调用知识整理模型；“自动整理”进一步生成有引文的知识节点和关系。扫描文字识别仍遵循已配置的 OCR 策略，语义索引使用配置的嵌入服务。

会话内 `knowledge_ingest` 和兼容工具 `guideline_ingest` 使用 `sourceId` 从本次可访问附件读取全部现有文本，拒绝用模型读取的预览替代附件。无附件的文本可直接保存，但全文范围标记为待核对。明确的摘录标记为非全文。会话附件若未保留原文件，入库不会声称已保留原件；已有缺页不会被自动补全。

`coverage` 区分全部提交内容已处理、存在缺页或识别缺口、摘录、未知范围。页数来自解析结果，正文中的页码用于核对覆盖；“完整”不表示来源真实或临床内容已经核实。视频画面仅为抽样，不标为完整视觉识别。旧文档没有覆盖记录时显示待核对，不自动升级为全文。

## 资料类型与格式

资料性质独立于文件格式。相同 Excel 文件可以是药品目录、实验室参考表或问答库；选择相应资料类型决定结构字段。

| 资料性质 | 整理字段 |
| --- | --- |
| 指南、共识 | 人群、推荐、条件、例外与禁忌、推荐及证据等级 |
| 教材、专著 | 概念、定义、章节、适用范围 |
| 论文、研究 | 设计、人群、干预、对照、结局、效应量、局限性 |
| 药品说明书 | 通用名、剂型规格、适应证、用法用量、禁忌、相互作用、特殊人群 |
| 检验、检查 | 项目、标本、方法、单位、参考区间、人群、实验室 |
| 量表、评分 | 项目、计分规则、阈值、解释、人群、验证范围 |
| 路径、操作规范 | 条件、步骤、分支、禁忌、终止条件、质量要求 |
| 病例报告 | 背景、时间线、干预、观察结果、局限性 |
| 患教、问答 | 问题、解释、行动建议、就医提示、人群 |
| 课程、经验笔记 | 主题、观点、情境、观察、局限性及时间位置 |

支持现有 PDF、DOCX、XLSX、文本、Markdown、CSV、TSV、JSON、图片、音视频和字幕入口。旧二进制 XLS 需先转换为 XLSX。图像和视频的文字抽取不等于医学影像、病理或手术画面的诊断理解。

XLSX 按工作表和非空行提取，保留表头、行号、单元格地址、合并来源和隐藏属性；单元格空白不补零。多列的首个非空行作为候选表头，复杂多层表头仍需核对原表。公式只读取缓存值，不执行公式、宏或外部链接。CSV/TSV 支持引号、分隔符转义和单元格内换行。跨行关联需要读取相邻原文，不能把不同剂型、单位或人群的记录拼接成一条结论。

## 分块和索引

结构分块识别现有文本中的 Markdown 标题、简短章节标题、页码、工作表及 Markdown 表格。原文切片与继承的标题、表头分别保存，引用行号始终指向原文。长行完整拆分并记录列偏移，不丢弃过长段落。当前使用保守字符预算，而非特定模型 tokenizer。

正文上限为 200 万字符，与后台解析限制一致。通用 PDF 文本路径不推断复杂表格结构；未可靠保留的版式不能仅靠分块恢复，需对照原件。

每 16 块请求一次嵌入。SQLite 保存模型、连接及分块内容指纹与各块向量检查点，全部批次成功后再提交文档向量。失败保留已完成批次，重试可复用；重启中的任务标为中断。正文或模型配置变化时不复用不匹配的检查点。每份文档记录总块数、处理块数、已发布向量数量和安全的错误原因。

“检查嵌入连接”执行实际的短文本请求。配置存在与连接验证分别显示。单文档重试为后台任务；全库重建逐文档处理，返回失败清单，不把部分完成报告为全部成功。

## 检索与图谱

先按知识库、类别、年份、机构和来源状态选择文档，再执行向量召回，防止其他库占满候选。失败或处理中资料不使用旧向量；原文关键词检索继续可用。

词法候选使用原有短术语匹配规则，排序增加 BM25 长度与词频归一化。英文及数字分词，中文使用双字词；目前不是完整医学术语分词器。关键词、向量及图谱出处使用 RRF 融合，完整术语匹配优先。bge-m3 的向量候选阈值为 0.45，其他模型保留 0.35；需要按具体模型和语料评估，阈值不是医学证据置信度。英文多词查询允许至少六成词匹配后进入 BM25 排序，同时保留数字约束和完整匹配优先。当前没有额外部署神经重排序模型。

配置聊天模型后，查询可生成最多两条英文翻译或关键词变体，与原问题独立检索，再按结果的来源分块融合。仅向模型发送查询，不发送文档全文；变体不作为证据。每次生成最多等待 12 秒，失败回退原查询；短期缓存按模型隔离。`localOnly` 和带连字符的精确编号查询跳过改写。改写会增加延迟和少量模型用量，仍需核对召回证据中的人群、数值、单位和适用条件。

`knowledge_read` 返回逐行 L 标记；`knowledge_cite` 核验连续引文并生成带文档内容哈希的原文链接。引用打开后高亮准确行区间，原文已变更时提示重新核对。核验不会补写原文或判断临床结论是否成立。图谱引文允许忽略排版空白和英文跨行连字符，并在当前批次内唯一定位后保存真实原文与行号；多处匹配且无法通过指定范围消歧时拒绝保存。

图谱抽取按最多 40 行或约 3600 字符分批；持续校验失败的较大批次自动拆分，网络和鉴权错误不会触发拆分。批次计划与已成功范围持久化，旧任务按真实行范围续跑，不按新版批次大小重新解释历史进度。纯参考文献、版权等批次不据题目生成医学结论。全部批次处理完成与图谱内容经过专业复核是不同状态。

图谱按实体名称及原文中明确出现的别名找到种子，沿一跳关系收集有出处的原文范围，并限制到当前可访问文档。不同来源及版本的引文分别保留；仅完全相同的类型和规范化名称合并节点，不自动合并临床推荐。别名必须在对应引文中出现；结构字段按资料性质和医学实体类型共同约束：指南中的药物也可保存用法用量，论文中的指标也可保存单位。字段值和引文均需通过连续原文校验。关系含义仍待人工复核，不能仅因引用存在就视为推荐成立。

### 医学图谱构建与更新

在每个知识库的「知识图谱」页点击「生成知识图谱」或「更新知识图谱」，确认使用当前聊天模型后开始后台处理。更新按原文内容哈希和医学抽取版本判断待处理资料；未变化且已完成的结果复用，运行中的任务不重复提交。任务逐份排队并保存分段进度，可离开页面、停止或失败后继续。更新失败时仍可查看上一版有据结果，已停用资料不进入图谱。旧抽取版本在更新时重新提取。

节点区分疾病、诊断、症状、体征、药物、检查、指标、治疗、诊疗路径、人群、禁忌、不良反应和随访。关系区分诊断依据、鉴别诊断、适应证、推荐治疗、禁忌、不推荐、相互作用、治疗步骤和随访监测；每条关系保留明确陈述、条件性、可能或否定的语气。条件性关系必须附原文条件，人群、剂量疗程、例外、推荐等级和证据等级分别保存。治疗阈值不能作为诊断阈值，“不推荐”不能自动提升为“禁忌”。这些校验并不替代专业核对。

画布按关联布局，类型使用不同颜色，连线有方向；多个来源的同义关系在画布中合并显示数量，详情保留每处原文。可拖动画布、缩放、搜索名称和有据别名，按实体类型、关系类型或关联主题组筛选。主题组使用连通关系划分，不代表医学分类。点击节点探索邻居，点击连线核对来源及条件，原文链接携带内容版本。大图默认展示关联数较高的 90 个节点，可扩展至 250 个；搜索覆盖全部节点。

### 流程图与思维导图

同一构建任务按每个分段的实际内容提取结构图，保存到 `diagrams`。明确的先后步骤、条件分流与复评回路适合流程图；明确的章节归属、分类和主题层级适合思维导图。指南中的并列推荐不自动变为治疗步骤，文件类型本身也不决定图形。没有足够结构依据时保留关系图，不补造流程或分类。

每张结构图最多 12 个节点、16 条连线，每批最多两张。节点与连线都有连续原文、行号和内容版本；分支条件逐字摘录，不自行补“否则”分支。流程图校验起点、可达性与判断条件，允许原文支持的循环；思维导图校验单一中心、单一父主题和树结构。结构及引文校验不能证明医学语义正确，结果仍标为待核对。

知识图谱页提供「自动选择、关系图、流程图、思维导图」。自动模式在实际提取到流程时优先展示流程，否则展示已有主题层级，最后回到关系图。切换视图不调用模型。结构图按资料与分段单独保存，可选择图、滚动、缩放、点击节点或连线打开原文；不同指南和版本不会合并成一条诊疗路径。旧资料需点击「更新知识图谱」按新版规则重新提取。

当前结构图基于已提取文字，不保证复原 PDF 原始图形版式，也不跨分段推断完整路径。复杂流程跨页或跨批断开时，应结合原文核对局部图。

## 设计参考

实现使用现有 Node.js、SQLite 和 LanceDB，不引入外部知识库服务。以下开源方案作为模块边界和处理思路的参考，未直接移植其代码：

- [RAGFlow 检索实现（v0.20.5）](https://github.com/infiniflow/ragflow/blob/v0.20.5/rag/nlp/search.py)：检索前应用文档范围过滤、多个召回来源与引用回查。
- [RAGFlow 任务执行器（v0.20.5）](https://github.com/infiniflow/ragflow/blob/v0.20.5/rag/svr/task_executor.py)：后台任务、分批处理和进度。
- [Docling 结构分块](https://docling-project.github.io/docling/concepts/chunking/)：正文结构、标题上下文与表头传递。当前实现不等同于集成 Docling 的版面识别模型。
- [Graphify](https://github.com/Graphify-Labs/graphify)：内容版本缓存、关系来源、节点关联探索与分组展示；本项目使用医学抽取约束和现有后台队列，不引入代码 AST 抽取或无出处推断边。
- [LightRAG](https://github.com/HKUDS/LightRAG)：图谱信息与原始文本块共同参与召回。
- [OpenSPG KAG](https://github.com/OpenSPG/KAG)：领域字段约束及知识与原文互相索引。

功能回归覆盖附件范围、断点续建、实际 LanceDB 范围过滤、Excel 原件上传及字段出处。合成测试只能验证机制，医学答案质量还需使用有标准出处的代表性资料评测。

## 知识库工作区

知识库按「资料、检索、知识图谱」组织。统一导入入口支持批量文件，可选择仅建立索引或同时生成图谱；部分上传失败时保留失败文件供重试。后台任务保留已完成、失败和中断记录。当前库和工作区入口可在刷新后恢复。

资料列表展示文档、版本及必要的处理状态，来源信息可在更多操作中核对；记录来源审核不会自动消除全文缺口或修复索引。检索、统计和任务按当前库隔离。检索条件与结果在原文阅读返回后保留，继续问答时携带当前库、来源筛选和候选出处，先生成可编辑草稿。

Excel、CSV、TSV 可按工作表预览、筛选行并分页查看，保留单元格位置、原始行号、隐藏标记、合并来源与公式缓存说明。既有表格可从保留的原件重新读取预览；不调用模型、不执行公式、不改动已入库内容。只有与保存原文一致的表格行参与引用自动定位。当前预览不是结构化计算引擎，多层表头与复杂合并单元格仍需结合原件核对。

先建索引、后生成图谱的流程会继承保留的原件和定位信息。图谱支持按主题类型、名称筛选及分组浏览，点选后查看关联关系与各自来源；生成条目继续标记为待核对。

回答引用、检索结果与图谱依据可在右侧溯源面板核对，不切换当前页面；窄屏使用覆盖式面板。原文按引用位置高亮；来源详情、原件和提取文本集中在“更多”中，旧引用、已停用来源及不完整内容仍直接提示。连续选择引用会更新同一面板；关闭或按 Esc 后继续原来的阅读与输入。读取失败可在面板内重试。

表格引用默认显示结构化表格，并根据原文定位映射自动选择工作表、分页和引用行。表头不重复列为数据；手动切换工作表、分页或筛选隐藏了引用时可返回引用行。单元格位置可按需显示，提取文本仅作为辅助核对入口。映射失效或表格读取失败会明确提示，仍保留提取文本与原件核对路径。
